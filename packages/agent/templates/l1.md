# Level: L1 — Client/Product Wizrd

You are at a client or product level. This wizrd owns the engagement context — who the client is, what we're building, current state, decisions made.

## What L1 Is
- The client's project hub — context, plans, worklogs, knowledge base
- Git submodule of L0, but works independently (client can have access to just this repo)
- Contains L2 service repos as submodules under `services/`
- The CLAUDE.md here is the source of truth for this client engagement

## What You Can Do at L1
- Read/write worklogs: `worklog/`
- Read/write knowledge base: `knowledge-base/`
- Update CLAUDE.md with engagement status, decisions, next actions
- Navigate to L2 for code work
- Run workflow skills: plan, execute, review
- Run client-specific skills if they exist: check `.claude/skills/`
- Use client-specific agents if they exist: check `.claude/agents/`

## What You CANNOT Do at L1
- Write application code — that's L2, navigate to `services/{service}/`
- Make assumptions about what services exist — always check `ls services/`
- Modify files that belong at L0 (company knowledge, global skills)

## First Thing to Do at L1
1. Read `CLAUDE.md` — it has client context, active services, current state, and decisions
2. Check services: `ls services/`
3. If services are empty/missing: `git submodule update --init --recursive`
4. If still empty: check CLAUDE.md for where the actual repos live (may be in external org)

## Working with Services (L2)

```
# Initialize all services
git submodule update --init --recursive

# Enter a service
cd services/{service}/

# Fetch remote branches
git fetch --all
git branch -a

# Check what's on a feature branch vs main
git log origin/main..{branch} --oneline    # commit count
git diff origin/main..{branch} --stat      # files changed
git diff origin/main..{branch}             # actual diff
```

## Common L1 Gotchas
- **Submodules not initialized**: Run `git submodule update --init --recursive` — don't clone manually
- **Submodule in detached HEAD**: Normal for submodules — `cd` in and `git checkout main` if needed
- **No .gitmodules**: The L1 wizrd may not have services as proper submodules yet. Check CLAUDE.md for repo locations, and flag as setup gap
- **External org repos**: Some clients (Symfio, Kontentino) have repos in their own GitHub org. The L1 CLAUDE.md documents this — read it before trying to find repos in `Digitaliko/`
- **Stale submodule pointers**: The L1 may point to an old commit in a service. `cd` into the service and `git fetch --all` to see what's actually on remote
