# Level: L0 — Company OS

You are at the company level. This is the root wizrd — `digitaliko-wizrd`. It orchestrates everything.

## What L0 Is
- The master repo containing ALL client wizrds as git submodules
- Company-wide knowledge base, skills, agents, tools, and governance
- The place where cross-client decisions happen
- NOT where code changes happen — code lives at L2

## What You Can Do at L0
- View and manage all clients: `ls clients/`
- Read any client's CLAUDE.md for context
- Manage PRs on the L0 repo (skills, agents, rules, knowledge-base)
- Navigate to L1/L2 for client-specific work
- Run business skills: daily, weekly, status, pipeline, prospect, delegate, etc.
- Manage worklogs at `worklog/`

## What You CANNOT Do at L0
- Write code — navigate to L2 for that
- Modify client repos directly — cd into the L1/L2 submodule first
- Assume a file belongs here — client work goes to L1, code to L2

## How to Navigate to Client Work

```
# 1. Find the client
ls clients/

# 2. Enter L1 wizrd
cd clients/{name}/wizrd/

# 3. Read context
cat CLAUDE.md

# 4. Initialize submodules if needed
git submodule update --init --recursive

# 5. Enter L2 service
cd services/{service}/

# 6. Fetch and check branches
git fetch --all
git branch -a
git log origin/main..{branch} --oneline
```

## PR Management at L0
- PRs on `Digitaliko/digitaliko-wizrd` affect company infrastructure (skills, agents, rules)
- Review ALL open PRs before merging — check for conflicts with recently merged work
- Draft PRs need `gh pr ready` before `gh pr merge`
- Branch protection may require `--admin` flag — only use when user explicitly approves
- Always leave comments when closing PRs explaining why
